## 一、整改背景与核心缺陷诊断

在前期迭代中，系统虽然建立了宏观周期、技术发现、产业扩散、企业生存与回测流程，但经第三轮深度审计，发现以下阻断性可信度缺陷：

1. **样本外验证门禁被自生标签击穿**：原 `validate_out_of_sample()` 允许调用方直接传入由模型自身预测值构造的验证标签 (`predict() + 0.1`) 和超宽松阈值，使未验证模型轻而易举晋升为 `VERIFIED_PRODUCTION`。
2. **实验模型渗透至非对称收益推演**：`OpportunityPoolManager` 将实验模型 (`UNVERIFIED_RESEARCH`) 的未验证倍数传入蒙特卡洛引擎，并配合硬编码 25x/45x 估值扩张，虚构出约 18% 的“10倍超额收益概率”。
3. **回测缺乏历史截面独立模型训练**：回测在 2021 年切片点虽做了时序指标查询，但直接使用 2026 年训练好的模型对象，甚至包含了 2024 年才成熟的未来标签，违背严格 Walk-Forward 回测铁律。
4. **Cox 生存模型时间单位与缺失财务漏洞**：存在 `max_duration > 15` 的粗糙年份判断，导致观察期小于 15 个月的月度队列被误判为年份；关键财务指标缺失时自动填入 24/45/35 等默认数值。
5. **预测记录与回测结果被静默覆盖**：使用 `INSERT OR REPLACE` 静默覆盖历史预测与回测记录，缺乏不可篡改版本追踪；数据库迁移采用 `except Exception: pass` 静默吞没错误。

## 二、第三轮定向整改措施与技术落实

### 1. P0-01：独立样本外验证与生产模型准入门禁重构
- **独立验证数据结构与审计元数据**：
  在 `src/core/types.py` 中定义规范的 `OOSValidationSample` 与 `OOSValidationDataset`，强制包含：`sample_id`、`dataset_version`、`feature_snapshot_id`、`decision_date`、`feature_available_at`、`label_period_end`、`label_observed_at`、`label_source`、`label_quality_status`、`source_record_id`、`data_quality_status`、`is_synthetic`、`is_model_generated`。
- **6 步独立准入审计流水线 (`ModelValidationService`)**：
  1. **数据真实性校验**：验证集质量状态必须为 `VERIFIED`，且绝不包含合成数据 (`is_synthetic=False`) 或模型自生标签 (`is_model_generated=False`)。包含模拟/自生标签直接拒绝生产晋升。
  2. **时序与标的隔离校验**：严格校验测试集与训练集样本 ID 无交集；无标的与时序窗口重叠；特征公开时间早于等于决策时间；标签观察期终点及公布时间早于等于评估截止日。
  3. **独立样本外评测**：独立评测 LightGBM MAE 与 Cox C-index。
  4. **基准模型对照**：LightGBM 必须显著超越简单基准 (Naive Baseline，全预测训练集均值/中位数预测)；Cox 模型必须超越随机基准 (0.50)。
  5. **生产硬性不可逾越上限**：LightGBM Max MAE $\le 2.0$；Cox C-index $\ge 0.60$。调用方传入更宽松阈值时被系统自动截断回硬性上限，无法绕过。
  6. **执行类型与审计日志**：区分 `FORMAL_PRODUCTION_AUDIT`、`TEST_ONLY` 与 `EXPERIMENTAL`。工程测试只能生成 `TEST_ONLY` 记录，模型阶段保持 `BENCHMARK`，绝不晋升生产状态。

### 2. P0-02：实验模型与非对称收益模拟物理隔离
- **执行类型与免责声明强制绑定**：
  `AsymmetricPayoffEngine.simulate_payoff` 引入 `simulation_type: SimulationType` 与 `is_verified: bool` 参数，支持 `FORMAL_PREDICTION` 与 `HYPOTHETICAL_SCENARIO`。
- **正式 10 倍超额收益概率清空**：
  当输入为实验性模型 (`UNVERIFIED_RESEARCH` / `EXPERIMENTAL`) 或处于情景推演时，正式投资决策指标 `prob_10x_super_return_pct` 严格为 `None`，估算值置于 `scenario_prob_10x_pct`，并附带明确免责声明：
  > “情景模拟结果仅供宏观与产业弹性敏感性参考，不构成针对特定企业的真实收益概率承诺。”
- **消除虚假估值扩张**：正式预测严禁在缺失真实估值数据时使用硬编码 25x/45x 扩张替代；综合决策层若未经验证，校准概率与正式 10 倍概率严格为 `None`。

### 3. P0-03：严格 Point-in-Time 滚动回测历史独立训练
- **历史切片时点模型独立训练**：
  回测引擎在历史截面 $T$ (如 2021-12-31) 执行 `train_historical_forecaster()`，提取仅在 $T$ 时点已公开且标签已成熟的数据 ($published\_at \le T$ 且 $label\_period\_end \le T$) 拟合独立历史模型，模型版本明确标识为 `hist_20211231`。
- **杜绝未来标签泄漏**：2021 年时点训练集中，2024 年才成熟的 3 年期标签严格置为 `None`。
- **模型可用性状态机 (`MODEL_UNAVAILABLE_AS_OF_DATE`)**：
  若历史时点可用成熟样本不足以训练模型 (< 5 条)，明确标记为 `MODEL_UNAVAILABLE_AS_OF_DATE`，绝不强行输出正式预测。
- **未成熟期与审计锚定日拦截 (`NOT_MATURED`)**：
  评估日若超过审计锚定日 (`audit_as_of_date`，默认 2026-11-11) 或尚未满观察周期，结果状态必须为 `NOT_MATURED`，绝不作为分母惩罚计入失败。

### 4. P1 缺陷定向补修
- **Cox 生存模型时间单位标准化**：
  彻底废除 `max_duration > 15` 的年份判断启发式，统一标准化为 `MONTHS` (12m/36m/60m)。对于最大观察期小于 12 个月的队列，超过跟踪期的外推严格返回 `None`。
- **关键财务指标缺失拦截**：
  财务数据缺失核心指标 (如 `debt_ratio`, `gross_margin`) 时，直接返回 `INSUFFICIENT_DATA`，绝不自动填充默认值。
- **预测历史与回测记录防篡改版本化**：
  对同一时点同一标的重复生成预测时，通过版本化修订 ID (如 `FC_TOPIC_EMBODIED_AI_20240101_v2`) 进行增量存储，彻底废除 `INSERT OR REPLACE` 静默覆盖。
- **数据库迁移可靠性与完整性保障**：
  引入 `schema_migrations` 追踪表，废除 `except Exception: pass`。迁移步骤执行详细日志与错误记录，遭遇不可恢复错误时抛出 `RuntimeError`，并在迁移后执行关键表结构完整性验证。

## 五、结论与合并建议

在本次第三轮定向整改中，系统建立了**全流程独立的样本外验证审计流水线**，修复了**模型自生验证作弊**、**实验模型收益泄漏**、**回测未来模型穿越**、**Cox 队列单位混淆**以及**预测静默覆盖**等全部关键隐患。

### 明确结论判定：
- **结论 B**：**系统架构、数据门禁与代码工程整改完全达标，具备合并进入主干分支条件。但在逐项核准的跨周期生产级真实训练数据集就绪前，全系统保持双轨运行——研究候选池正常提供客观分析，正式预测排名严格返回空 (`NO_VERIFIED_FORECASTS`)，真实反映系统能力边界。**

建议项目维护团队：
1. **立即合入 PR #3** 到 `main` 分支，巩固可信度整改防线。
2. 组织下一阶段重点攻坚：基于正式核验管道扩充生产级经过逐项审计的标的队列。
