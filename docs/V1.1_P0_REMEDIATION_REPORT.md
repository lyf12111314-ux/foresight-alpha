## 一、整改背景与核心缺陷诊断

在 V1.0 及前期快速迭代中，系统虽然初步建立了宏观周期、技术发现、产业扩散、企业生存与回测流程，但经深度代码与数据审计，发现了以下阻断性 P0 数据真实性与预测可信度缺陷：

1. **`MANUAL_REFERENCE` 绕过正式训练准入门禁**：人工录入待逐项核实的样本直接激活了 `fit_verified()`，导致未验证模型被打上“已验证生产模型”虚假标签。
2. **未来标签信息泄漏**：2022 年底的技术样本，其 5 年期观察窗口终点为 2027-12-31。在 2026-11-11 审计时点，该标签尚未到达终点，却在数据集中被硬编码为已验证真实数值 (4.90)。
3. **幸存者偏差**：技术训练集初期仅包含成功爆发赛道（大模型、机器视觉、光伏、mRNA等），完全缺乏证伪、退潮或放缓样本。
4. **企业生存队列协变量未经审计**：生存队列包含主观估计协变量（如未逐项审计的竞品数量与现金流断流月份），且缺乏规范的退市/破产类型界定。
5. **回测未来信息泄漏 (Lookahead Bias)**：在 `backtest/engine.py` 与 `opportunity_pool.py` 中，当历史切片点查询结果为空时，代码存在静默回退全表扫描 (`SELECT * FROM ...`) 逻辑，读取了未来数据。
6. **回测指标伪造**：回测引擎将 `(Precision@3 + Precision@5) / 2` 冒充为 `PR-AUC`；随机基准 (0.33) 与动量基准 (0.45) 采用硬编码常数而非动态真实测算。
7. **未成熟样本被误判为失败**：回测事实标签将观察期未满或证据不足的样本直接赋值为 0 (失败)，严重扭曲了评估精确率与召回率。
8. **研报事实与成绩造假**：自动研究报告中硬编码了“2018年第四季度捕获”、“第六次技术浪潮繁荣期”、“66.7% 回测准确率”与“0.18 Brier Score”，并使用 Python 内置 `hash()` 冒充 SHA-256 数字签名。

## 二、整改措施与逐项技术落实

### 1. P0-A：重建真实数据与正式训练的准入门禁
- **多维状态分离**：在 `src/core/types.py` 中彻底废弃单一 `TRAINED` 状态混淆一切的模式，正式拆解为四项独立布尔标记与阶段枚举：
  - `ModelStage`：`UNTRAINED`、`EXPERIMENTAL`、`BENCHMARK`、`VERIFIED_PRODUCTION`。
  - `is_algorithm_fitted`：算法是否已收敛拟合。
  - `is_data_verified`：训练数据是否经审计逐项核验为 `VERIFIED`。
  - `is_out_of_sample_validated`：是否完成跨周期样本外时序验证。
  - `is_calibrated`：预测概率是否通过独立经验校准。
- **强制准入门禁**：
  - `LightGBMGrowthForecaster.fit_verified()` 与 `CompanySurvivalEngine.fit_verified()` 强制检查数据溯源与质量状态。
  - 凡输入包含 `MANUAL_REFERENCE`、`UNVERIFIED`、`SYNTHETIC` 或普通无来源 NumPy 数组，直接拒绝正式训练，保持 `MODEL_NOT_TRAINED` / `INSUFFICIENT_DATA`，并返回显式拒训原因。
- **独立实验模式隔离**：
  - 新增 `fit_experimental()` 接口，专供人工历史参考数据 (`MANUAL_REFERENCE`) 进行算法演示与学术推演。
  - 实验模型标记为 `ModelStage.EXPERIMENTAL`，其预测输出 `is_verified` 严格锁定为 `False`，状态输出为 `UNVERIFIED_RESEARCH`。

### 2. P0-B：技术样本库与双时间标签重构
- **双时间结构**：在 `src/ingestion/tech_dataset.py` 中为每条样本建立两组严格时标：
  - 特征时间：`base_date`、`feature_published_at`（必须 `<= base_date`）、`feature_ingested_at`。
  - 标签时间：`label_period_end`（基准日 + 期限）、`label_status`、`target_growth`。
- **2026-11-11 截止时点成熟度拦截**：
  - 2022 年底样本的 5 年期标签（截止日 2027-12-31）`> 2026-11-11`，状态设为 `LabelMaturityStatus.NOT_MATURED`，`target_5y` 严格设为 `None`。
  - 2021 年底样本的 5 年期标签（截止日 2026-12-31）`> 2026-11-11`，状态设为 `LabelMaturityStatus.NOT_MATURED`，`target_5y` 严格设为 `None`。
  - 2020 年及以前的 5 年期标签（截止日 `<= 2025-12-31`）正常标记为 `MATURED` 并保留真实观测值。
- **负样本与退潮赛道引入**：
  - 增加 `TOPIC_ROOM_TEMP_SUPERCOND`（LK-99 常温超导，2023年热度后复现证伪，1年期增长 0.22 暴跌）。
  - 增加 `TOPIC_GOOGLE_GLASS_AR`（早期消费级单目 AR 智能眼镜，2013-2015 商业化遇冷）。
  - 增加 `TOPIC_CONSUMER_3D_PRINTING`（早期消费级桌面 3D 打印，2014-2016 潮退洗牌）。
  - 增加 `TOPIC_BLOCKCHAIN_DAO`（早期智能合约 DAO 组织，黑客事件后陷入停滞）。
  - 总样本扩充至 45 个历史截面，有效平衡模型分布，消除幸存者偏差。

### 3. P0-C：企业生存数据集与 Cox 模型整改
- **事件类型规范化**：引入 `DistressEventType` 枚举，严格区分：
  - `DELISTING`（乐视网、康得新、暴风集团、保千里、雏鹰农牧、信威集团）
  - `BANKRUPTCY`（凯迪生态）
  - `RESTRUCTURING`（众泰汽车）
  - `CENSORED_ACTIVE`（汇川技术、宁德时代等正常存续样本）
- **协变量审计与缺失处理**：
  - 明确标明 `observation_window_months`。
  - 在 `strict_audit_only=True` 模式下，未逐项核准的外部估计协变量（如 `competitor_count` 与估算现金消耗月数）自动置为 `None`。
- **禁止模拟或待核验数据产生正式破产概率**：
  - 历史违约队列为 `MANUAL_REFERENCE`，仅允许进入 `fit_experimental` 模式。
  - 生存引擎预测结果标记为 `UNVERIFIED_RESEARCH`，`is_verified=False`，附带明确免责声明，杜绝将统计估计误导为确定性信用断言。

### 4. P0-D：严格 Point-in-Time 回测与评估指标重构
- **彻底清除全表回退泄漏逻辑**：
  - 彻底删除 `src/decision_engine/opportunity_pool.py` 及 `src/backtest/engine.py` 中 `if df.empty: df = query_df("SELECT * FROM ...")` 的未来信息泄漏逻辑。
  - 切片时点无数据时，明确返回空或标记为缺失，绝不读取未来时序。
- **事实标签严谨状态机**：
  - 引入 `GroundTruthOutcome`：`SUCCESS`、`FAILURE`、`NOT_MATURED`、`INSUFFICIENT_EVIDENCE`。
  - 若 `evaluation_date` 尚未满观察期限，状态为 `NOT_MATURED`；若历史记录缺失，状态为 `INSUFFICIENT_EVIDENCE`。
  - 在评估 Top-K 精确率与召回率时，**未成熟样本与证据不足样本绝不作为分母惩罚计入失败**。
- **真实 PR-AUC 梯形数值积分**：
  - 在 `src/backtest/metrics.py` 中实现标准 Precision-Recall 曲线梯形数值积分算法：
    $$\text{PR-AUC} = \sum_{k=1}^{N} \frac{P_k + P_{k-1}}{2} \times (R_k - R_{k-1})$$
  - 彻底取缔原先用 `(prec_3 + prec_5) / 2` 伪造 PR-AUC 的做法。
- **动态对照基准计算**：
  - 彻底废除固定 0.33（随机基准）与 0.45（动量基准）。
  - 随机基准基于当前候选池正样本真实比例动态计算：$P_{\text{random}} = \text{Positives} / N$。
  - 动量基准基于当前候选池历史动量指标（如 `velocity_1y`）排序取 Top-K 的真实命中率动态计算。

### 5. P0-E：研报虚构内容与数字签名清理
- **清理硬编码结论**：
  - 捕获时间：动态读取检测时标，缺失时显示“尚无可靠数据”（删除硬编码“2018年第四季度”）。
  - 宏观周期：动态读取 HMM 诊断状态，无依据时不妄断康波繁荣（删除硬编码“第六次康波繁荣期”）。
  - 回测实证：仅在具备实际回测指标时展示，未回测时显示“尚无可靠数据”（删除硬编码“66.7%”及“0.18 Brier Score”）。
- **真实 SHA-256 防篡改签名**：
  - 引入 Python `hashlib.sha256()`，基于 `topic_id`、截面日期、综合分与时间戳计算标准 64 位哈希签名，彻底取代内置不稳定 `hash()`。

## 五、未解决问题与下一阶段工作建议

1. **真实已核验样本库建设 (P1)**：
   当前技术样本与企业违约队列虽已具备真实公开历史出处，但整体标记为 `MANUAL_REFERENCE`。下一步需通过自动化财报爬虫与学术 API 数据管道逐项核验入库，将质量状态晋升为 `VERIFIED`，以激活首个正式生产模型 (`VERIFIED_PRODUCTION`)。
2. **独立经验概率校准器 (P1)**：
   系统目前已严格将未校准模型的预测概率字段置为 `None`。后续需引入 Platt Scaling 或保序回归 (Isotonic Regression)，并在滚动时间截面上独立计算 Brier Score，实现真正经过统计校准的成功概率。
3. **滚动前瞻验证 (Walk-Forward CV)**：
   目前已完成 Point-in-Time 回测引擎物理时钟隔离。后续需在大规模历史切片（2015-2024 每半年度）上批量执行滚动前瞻回测，沉淀系统级真实超额 Alpha 数据。
