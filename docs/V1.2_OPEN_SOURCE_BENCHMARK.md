## 二、五大核心项目代码级深度剖析

### 1. Microsoft Qlib (`microsoft/qlib`, MIT)
- **核心源码依据**：
  - `qlib/data/dataset/handler.py`：`DataHandler`、`DataHandlerLP`（`fit_process_data` / `process_data(with_fit=False)`）
  - `qlib/data/dataset/__init__.py`：`DatasetH`（`prepare`、`get_min_time`、`get_max_time`）、`TSDataSampler`
  - `qlib/workflow/task/gen.py`：`RollingGen`、`MultiHorizonGenBase`（含 `label_leak_n` 参数防跨期标签泄漏）
  - `qlib/contrib/model/gbdt.py`：`LGBModel`
  - `qlib/backtest/backtest.py`：`backtest_loop`、`collect_data_loop`
- **架构优势**：
  - `DataHandlerLP` 将“只在训练集 `fit` 的特征处理器（`infer_processors` / `learn_processors`）”与测试集只读 `process_data(with_fit=False)` 严格分离，从机制上杜绝归一化/缺失填充泄露；
  - `RollingGen` 与 `MultiHorizonGenBase(label_leak_n)` 显式在训练集末尾与测试集起点之间留出标签成熟间隔，防止多期预测标签跨界污染。
- **不适合直接整体引入的部分**：
  - `qlib/backtest/backtest.py` 的 `backtest_loop` 面向**日频/日内证券交易撮合**（依赖本地二进制特征库、交易所订单簿、持仓与手续费引擎），而 Foresight Alpha 当前核心是**跨年度新兴技术与产业主题研究（3–10 年长周期）**，强行引入 Qlib 全套本地二进制数据仓与交易撮合回测会带来极高的迁移与维护负担。
- **结论**：**借鉴架构，不整体引入**（仅吸收 `DataHandlerLP` 的 fit/transform 隔离与 `RollingGen(label_leak_n)` 的时间窗口防泄漏设计）。

### 2. BERTopic (`MaartenGr/BERTopic`, MIT)
- **核心源码依据**：
  - `bertopic/_bertopic.py`：`BERTopic`（L88）、`fit_transform`（L395）、`transform`（L545）、`partial_fit`（L649）、`topics_over_time`（L797）、`merge_topics`（L2101）、`reduce_outliers`（L2380）
- **对比 Foresight Alpha 现状**：
  - 当前 `src/tech_discovery/clustering.py` 使用 `TfidfVectorizer + DBSCAN` 且**未接入** `IngestionPipeline` 与 `OpportunityPoolManager`；`src/decision_engine/opportunity_pool.py:78-85` 仍写死 6 个固定技术主题。
- **可复用与关键风险**：
  - **可复用**：`BERTopic` 可直接作为候选主题发现离线/批处理引擎（结合语义嵌入替代纯 TF-IDF 词袋）；`partial_fit` 支持按时间批次增量更新，配合 `topics_over_time` 观察主题演化；`merge_topics` 可抑制同义词分裂导致的重复主题。
  - **核心风险**：1) 若对全量 2018–2026 年论文一次性 `fit_transform`，再做 2020 年历史回测，**会引入严重的“未来主题词表泄露”**；因此历史回测必须按截断年 $T_0$ 仅使用 $\le T_0$ 文献增量拟合；2) 学术热点聚类存在高误报率（会议专题、综述合集易形成伪“新兴技术”），必须配合机构多样性（Shannon 熵）与持续期过滤，不能直接替代人工终审。
- **结论**：**V1.2 第二阶段选择性引入作为候选发现器**（与现有固定赛道池并行运行，严禁未经稳定性过滤直接自动入库）。

### 3. PyAlex (`J535D165/pyalex`, MIT) & OpenAlex Tutorials
- **核心源码依据**：
  - `pyalex/api.py`：`Paginator`（L308，支持 `method="cursor"` 游标分页）、`BaseOpenAlex`（L419，`filter` / `filter_gt` / `filter_lt` / `group_by` / `select`）、`Works`（L1029）、`Topics`（L1131）、`Institutions`（L1083）、`invert_abstract`（L229，从倒排索引还原摘要文本）。
- **对比 Foresight Alpha `src/ingestion/openalex.py`**：
  - 当前 `openalex.py` 手写 `requests` 请求，**存在三处硬伤**：1) L55 累加当前总 `cited_by_count` 作为历史年份引用；2) L61 用 `max(len(sample_institutions)*12, int(count*0.15))` 估算机构数；3) 未保存原始分页响应与游标断点。
  - 引入 `pyalex` 可直接复用其规范化过滤表达式、游标分页（突破单页上限）以及 `Topics` / `Institutions` 原生对象，并可直接使用 `invert_abstract` 为后续 BERTopic 主题发现提供真实英文摘要语料。
- **不可替代的时间审计纪律**：即使使用 `pyalex`，`Works` 的 `cited_by_count` 仍是查询当日累计值，必须在采集层显式按 `counts_by_year`（`year <= T_0`）截断，并留存原始 JSON 快照与 SHA-256。
- **结论**：**直接复用（P0 最高优先级）**。

### 4. PreScience (`allenai/prescience`, Apache-2.0)
- **核心源码依据**：
  - 4 大真实科研预测任务：`task_impact_prediction/`、`task_followup_prediction/`、`task_coauthor_prediction/`、`task_priorwork_prediction/`
  - `task_impact_prediction/dataset.py`：`create_evaluation_instances` 严格取固定月数窗 `citation_trajectory[impact_months - 1]` 并按论文日期排序，显式过滤轨迹长度不足 `impact_months` 的未成熟样本；
  - `task_impact_prediction/evaluate.py`：`compute_aggregate_metrics` 统一输出 `mae`、`r2`、`pearson`、`spearman`、`log_mae`、`log_pearson`；
  - 简单基准对照齐备：`baseline_poisson.py`、`baseline_negative_binomial.py`、`baseline_embedding_ridge.py`、`baseline_xgboost_regressor.py`。
- **对 Foresight Alpha 的启发**：
  - 彻底证明了**“科学预测必须先定义单一明确的可观测物理标签 + 固定观察期 + 对数空间指标 + 简单统计基准（Poisson / 负二项 / Ridge）”**，而不是用缺乏真实依据的综合增长倍数（如当前 `backtest/engine.py:208` 硬编码 `papers_count >= 1.9` 或把论文倍数映射为 10 倍股票概率）。
- **结论**：**深度借鉴任务定义、成熟度截断与对数误差 + 简单基准评估范式（P0）**，无需引入其大模型微调代码（`finetune_lora.py`）。

---

### 5. Microsoft RD-Agent (`microsoft/RD-Agent`, MIT)
- **核心源码依据**：
  - `rdagent/core/proposal.py`：`Hypothesis`、`ExperimentFeedback`、`HypothesisFeedback`、`Trace`（`get_sota_hypothesis_and_experiment`）
  - `rdagent/core/evolving_agent.py`：`EvoAgent`、`RAGEvoAgent`
  - `rdagent/scenarios/qlib/developer/feedback.py`：`QlibFactorExperiment2Feedback`、`QlibModelExperiment2Feedback`
- **评估与定位**：
  - RD-Agent 提供了非常清晰的 `Hypothesis -> Experiment -> Evaluation -> Feedback -> Trace` 闭环抽象，但当前版本高度耦合 Qlib 因子/模型模板与 Docker 沙箱执行器。
  - 在 Foresight Alpha 的 **真实数据底座（Stage 1）与真实历史标签（Stage 3）尚未建好前**，过早引入 RD-Agent 只会让 Agent 在空库或噪声数据上“自动产生看似合理的假因子与假解释”。
- **结论**：**V1.2 前期不直接集成代码，仅借鉴其 `Hypothesis / Experiment / Feedback / Trace` 结构化实验日志模式（P2，第五阶段再落地）**。

### 6. 补充参考项目评估（FinRL / OpenBB）
- **`AI4Finance-Foundation/FinRL`（MIT, `v0.3.8`）**：聚焦深度强化学习交易策略（`Gym` 高频/日频动作空间），与 3–10 年新兴技术/产业演化研究目标不匹配，**不建议引入**。
- **`OpenBB-finance/OpenBB`（Release `ODP`）**：重型跨资产数据路由器，许可证字段在 GitHub 显示 `NOASSERTION`（含较多专有/第三方扩展约束），当前仅需在阶段 4 对接 A 股/美股公开财报与复权行情时作为接口设计参考，**不作为底层强依赖引入**。
