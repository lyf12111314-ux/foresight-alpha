## 二、最严重的 4 项工程与可信度隐患（代码实证）

1. **`src/decision_engine/opportunity_pool.py:149-154,176-180` 逻辑断链 Bug**：
   `forecaster_pred` 返回的 `is_verified` 字段未被复制到 `diffusion_res` 字典中，导致 `is_lgbm_verified = bool(diffusion_res.get("is_verified", False))` 恒为 `False`，即使未来模型通过 `TrustedValidationRegistry` 晋升为 `VERIFIED_PRODUCTION` 也无法生效。
2. **`src/ingestion/openalex.py:55,61` 与 `pipeline.py:247,287` 数据失真**：
   `cited_by_count` 泄露未来引用；机构数采用经验乘法估算；`entropy` / `novelty` 采用年份衰减公式替代真实熵值；GitHub 实时 Star 直接覆写指标。
3. **`src/decision_engine/opportunity_pool.py:160-169` 与 `survival_cox.py:434,437` 生存输入虚构**：
   机会池向生存引擎传入写死的 `topic_financials` 字典（且缺失 `competitor_count`），非正式模式下 `survival_cox.py` 静默补填 `24.0` 与 `1.0`。
4. **模块孤岛现象**：
   `tech_discovery/clustering.py`、`tech_discovery/semantic.py`、`value_chain/financial_audit.py`、`diffusion/baseline.py`、`macro/cycle_filter.py`、`macro/change_point.py` 均处于“已编码测试但未接入主业务链路”的孤岛状态；而 `dossier.py` 第 7 章却硬编码宣称“未发现红旗”。

## 三、现阶段核心短板归因

1. **真实历史数据供给极度匮乏**：宏观、企业财报、违约队列、多期技术训练集全为代码内 `MANUAL_REFERENCE` 元组。
2. **预测目标尚未按客观物理量分离**：`backtest/engine.py` 仍以“论文数量 >= 1.9 倍”充当唯一成功标签，未独立区分科研活跃度、产业营收与证券收益。
3. **动态发现与主链路脱节**：`OpportunityPoolManager` 仍遍历写死的 6 个主题，未打通基于论文文本的增量发现与稳定性过滤。
