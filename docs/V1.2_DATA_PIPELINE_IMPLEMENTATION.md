## 二、数据来源、快照存储与时间/资格定义

### 1. 快照存储规范 (`data/snapshots/openalex/`)
- 每次 HTTP 采集保留两类不可覆盖文件（均使用跨机器可验证的仓库相对路径）：
  1. 原始响应字节：`openalex__solid-state_battery__<year>_count_<sha16>.raw.json`（按内容哈希去重保存无损原始字节）；
  2. 采集事件审计元数据：`<prefix>_<utc_ts>_<sha12>_<rand8>.meta.json`（含完整请求 URL、参数、HTTP 状态、UTC 采集时间、代码版本 `v1.2-p0-data-provenance`、异常信息与三层状态标识）。
- 失败请求（超时 / `429` / 非 `200` / 畸形 JSON）同样写入 `.meta.json`，`raw_sha256=None`、`papers_count=None`，绝不伪造正常哈希或 `0` 篇记录。

### 2. 时间字段与四级历史资格定义
| 字段 / 枚举 | 精确语义 |
| :--- | :--- |
| `as_of_date` | 数据归属的统计年期末（如 `2020-12-31`），**不代表该日即可获取当前值** |
| `ingested_at_utc` | 系统实际向外部 API 发起并拿到响应的 UTC 时间戳（如 `2026-11-23T15:39:49`） |
| `verified_first_available_at` | 外部独立归档证明“预测时点当时即可获得该版本”的首次公开时间；无凭证时为 `None` |
| `citations_cutoff_year` | 从 `counts_by_year` 中截断累加引用的最大年份上限（排除了未来引用年份） |
| `CURRENT_SNAPSHOT_HISTORICAL_STATS` | 当下采集得到的历史年份统计：可用于现状分析，**严禁自动升级为严格 PIT** |
| `HISTORICAL_VINTAGE_UNAVAILABLE` | 缺少当时历史快照或可核验 `verified_first_available_at`，严格回测必须拒绝 |
| `STRICT_PIT_VERIFIED` | 同时满足有效磁盘 SHA-256、第三方历史版本时间 $\le T_0$，目前公开采集默认为 0 条 |
| `CURRENT_STATE_ONLY` | 如 GitHub Search API 实时 Star/Fork，仅限当下观察，历史回测禁用 |

### 实测版本漂移关键发现（诚实披露）
1. **PR #5 仅留存文档摘要而无落盘原始响应**，且即使在 `2026-11-13` 与 `2026-11-23` 之间（甚至当日 `13:37Z` 与 `15:39Z` 两小时之间），OpenAlex 历史计数均会随索引动态更新发生演变（例如 2020 年由 `1807` → `1847` → `1841`）；
2. **2020 年单篇 `counts_by_year` 亦存在重算漂移**（见 [2020_works_sample.raw.json](../data/snapshots/openalex/openalex__solid-state_battery__2020_works_sample_37ddff8b1bdc3ad6.raw.json)，SHA-256 `37ddff8b1bdc3ad6acf10c9290aa3799c6983b8900ac64d98ad9951a074f0e95`）：
   - `W3005210566`：`total_cited` `2528 → 2634`，`cited_in_2020=107`；
   - `W3010463153`：`total_cited` `1810 → 1871`，`cited_in_2020` 由 `90 → 88`；
   - `W3038591351`：`total_cited` `1578 → 1648`，`cited_in_2020` 由 `13 → 12`。
3. **泛匹配污染修复**：首次测试未加引号检索 `"solid-state battery"` 曾命中 `W3035965352`（*Array programming with NumPy*），已在 `pipeline.py` 与试点脚本统一修复为精确短语检索。
4. **OpenAlex 机构聚合上限实证**：`group_by=authorships.institutions.id` 对大领域受 `per_page=200` 上限截断，已对聚合响应同步存盘并诚实降级为 `SAMPLED_WORKS_ONLY`（`active_institutions=None`）。

## 五、未解决问题与下一阶段衔接

1. **全量机构去重成本**：超过 200 家机构的成熟学科需游标翻页拉取全量 `works` 才可得完整去重机构数（耗时及 API 配额更高）。
2. **外部历史归档（Vintage）缺失**：若需实现严格 PIT 学术/开源回测，后续只能依赖**持续按日定时自采沉淀真实快照**，或接入带有当年物理归档时间证明的历史库（如 PreScience 公开年份切分数据集）。
3. **企业与证券侧数据未接通**：`enterprise.py` 与 `macro.py` 内置 `MANUAL_REFERENCE` 参考集、以及可交易证券复权行情留待 V1.2 后续阶段替换。

## 六、PR #7 代码审查专项整改 (P0 + 3×P1)

1. **P0 — 严格历史 PIT 资格库内鉴权 (`OpenAlexCollector.evaluate_historical_pit_eligibility` / `PointInTimeBacktestEngine`)**：
   - 彻底禁止仅凭调用方传入的 `historical_eligibility=STRICT_PIT_VERIFIED`、`verified_first_available_at` 或 `raw_sha256` 放行；
   - 强制查证 `raw_snapshots` 库内登记记录、磁盘快照文件存在性及 SHA-256 实测重算一致、`source_authenticity_status='VERIFIED_HISTORICAL_ARCHIVE'`、非自宣 `vintage_evidence_source` 以及 `verified_first_available_at <= cutoff_date`，无可靠历史版本证据时一律返回 `HISTORICAL_VINTAGE_UNAVAILABLE`。
2. **P1 — `raw_records` 不可变采集历史留痕 (`DatabaseManager.append_raw_record` / `IngestionPipeline`)**：
   - 全面移除 `src/ingestion/pipeline.py` 中全部 8 处 `INSERT OR REPLACE INTO raw_records`；
   - 新增 `logical_record_id` 与自增 `ingestion_version` 审计列及版本查询接口 (`get_raw_record_versions` / `get_latest_raw_record`)，确保同主题同年度跨时点重复采集保留完整历史版本轨迹并按 `cutoff_date` 严格检索。
3. **P1 — 引用统计口径隔离 (`CitationCountScope` / `OpenAlexCollector` / `InflectionDetector`)**：
   - 将受 `per_page=10` 与 `cited_by_count:desc` 偏差影响的样本引用求和严格隔离写入 `sampled_citations_count`，标注 `citation_count_scope=SAMPLED_TOP_CITED_BIASED`，正式 `citations_count` 保持为 `None`；
   - 下游 `InflectionDetector.analyze_tech_acceleration` 明确校验口径，绝不将样本引用当作全领域总引用 (`citations_latest`) 输出。
4. **P1 — 特征级独立快照血缘绑证 (`feature_lineage` / `verify_feature_lineage` / `tech_metrics.feature_lineage_json`)**：
   - 为 `papers_count`、`citations_count`、`active_institutions` 分别绑定生成该特征的精确 `snapshot_id`、`raw_sha256`、`snapshot_path`、`scope` 与计算方法；
   - 仅篡改 `works_sample` 原始 JSON 文件即可被 `verify_feature_lineage(..., "citations_count")` 精准检出，且 `count`、`works_sample`、`institutions` 等各阶段快照及失败响应均统一持久化至 `raw_snapshots`。
