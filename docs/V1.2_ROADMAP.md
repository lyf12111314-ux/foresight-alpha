# Foresight Alpha V1.2 — 分阶段最小实现路线图 (`V1.2_ROADMAP.md`)

> **基线**：`main` (`05714281acb2f86bbf168c581aca54ec82f7974d`)  
> **执行纪律**：严格遵循 `AGENTS.md` 六阶段闭环；所有任务必须有明确输入、输出与可自动化执行的 `pytest` 验收标准。

## 第一阶段：真实数据底座与数据来源审计（P0 · 优先启动）

1. **目标**：消除 `src/ingestion/openalex.py` 未来引用泄露与启发式机构估算，建立原始 API 响应快照落盘与 SHA-256 校验机制，并修复 `opportunity_pool.py` 的 `is_verified` 传递 Bug。
2. **输入**：技术关键词列表（以固态电池等 10–15 个硬科技及对照主题起步）与指定年份区间（2013–2025）。
3. **具体功能**：
   - 使用 `pyalex`（`Works` + `Paginator(method="cursor")`）按 `publication_year` 拉取文献元数据与摘要；
   - 按 `counts_by_year` 中 `year <= T_0` 计算截至截断年的累计引用数，禁用全局 `cited_by_count`；
   - 基于作者机构 `institutions` 真实 ID 去重统计活跃机构数，删除 `max(len*12, count*0.15)` 估算；
   - 将每次 API 原始 JSON 响应保存至 `data/snapshots/openalex/` 并记录 SHA-256；
   - 显式标记 `github.py` 历史 Star 为 `NOT_ELIGIBLE_FOR_STRICT_BACKTEST`；
   - 修复 `src/decision_engine/opportunity_pool.py:149-154` 遗漏 `is_verified` 字段的问题。
4. **涉及代码模块**：`src/ingestion/openalex.py`、`src/ingestion/pipeline.py`、`src/core/database.py`（快照元数据列）、`src/decision_engine/opportunity_pool.py`、`requirements.txt`（新增 `pyalex`）。
5. **开源项目借鉴点**：`J535D165/pyalex`（`Paginator`, `Works`, `invert_abstract`）；`allenai/prescience`（按发布日期截断）。
6. **输出成果**：可复现的 OpenAlex 离线/在线快照集 + `raw_records` 真实 `raw_hash` 存证 + Bug 修复补丁。
7. **验收测试**：
   - 新增单测：构造 Mock 响应（`cited_by_count=2528` 但 `counts_by_year` 中 `2020` 为 `107`），断言 `as_of_date=2020-12-31` 入库引用数为 `107`；
   - 断言快照文件真实字节计算的 SHA-256 与数据库 `raw_hash` 一致；
   - 断言 `OpportunityPoolManager` 在模型 `VERIFIED_PRODUCTION` 时 `is_lgbm_verified` 正确传递为 `True`。
8. **依赖与风险**：OpenAlex 存在回溯补录新索引期刊带来的计数微调；需在报告中记录采集快照日期（`ingested_at`）以固化版本。
9. **完成条件**：`bash scripts/run_ci_checks.sh` 全绿、新增单测 100% 通过、独立 PR Review 通过。

## 第二阶段：新兴技术主题自动发现（P1）

1. **目标**：打破 `opportunity_pool.py:78-85` 硬编码 6 主题限制，建立基于真实英文摘要的增量主题发现、去重合并与稳定性过滤管道。
2. **输入**：第一阶段落盘的 OpenAlex 论文标题与 `invert_abstract` 还原摘要（严格过滤 `publication_date <= T_0`）。
3. **具体功能**：
   - 使用语义嵌入 + `BERTopic`（`fit_transform` 初始化基期、`partial_fit` 按年度增量更新）生成候选主题簇；
   - 使用 `merge_topics` + 余弦相似度合并近义词簇，生成稳定 `topic_id`；
   - 实现双门槛过滤器：连续 $\ge 2$ 年文献数正增长且机构分布 Shannon 熵 $\ge$ 阈值才晋升为研究候选池；
   - 输出 `candidate_topics` 列表供 `OpportunityPoolManager` 与预设主题池并行消费。
4. **涉及代码模块**：`src/tech_discovery/clustering.py`、`src/tech_discovery/semantic.py`、`src/decision_engine/opportunity_pool.py`、`requirements.txt`（`bertopic`）。
5. **开源项目借鉴点**：`MaartenGr/BERTopic`（`partial_fit`, `topics_over_time`, `merge_topics`）。
6. **输出成果**：带时间截断隔离的 `BERTopic` 候选主题发现引擎与主题演化记录。
7. **验收测试**：
   - 防未来主题泄露测试：分别在 `cutoff=2020-12-31` 与 `cutoff=2024-12-31` 运行发现，验证 2020 年词表中不包含 2021 年后才出现的新词簇；
   - 单点噪声过滤测试：注入仅在单年爆发的孤立会议词簇，断言被稳定性过滤器拦截。
8. **依赖与风险**：依赖第一阶段真实摘要数据；本地嵌入计算耗时需控制在单机 CPU/MPS 可接受范围（支持缓存嵌入向量）。
9. **完成条件**：离线 Mock 语料测试与至少 1 次真实 OpenAlex 摘要集抽样实验通过，CI 全绿。

## 第三阶段：真实成长标签与历史预测验证（P0/P1）

1. **目标**：围绕 Task A（文献扩散增速与高引突破）构建跨年度真实面板，在 `TrustedValidationRegistry` 上用真实数据完成 LightGBM 与简单基准（Ridge/Poisson/动量）的首次客观样本外评估。
2. **输入**：第一、二阶段生成的真实 `tech_metrics` 面板（覆盖 10–15 个技术主题，2013–2025 年）。
3. **具体功能**：
   - 构建 `Task A` 真实样本生成器：按截面年 $T_0$ 生成特征（均不含未来引用/未来 Star），按 $T_0+1, T_0+3, T_0+5$ 生成成熟标签（未成熟强制 `None`）；
   - 参考 `Qlib` `DataHandlerLP` 与 `RollingGen(label_leak_n)`，实现训练集 `fit` / 验证集只读 `transform` 处理器隔离；
   - 在 `src/diffusion/baseline.py` 补充 Ridge / Poisson 简单回归基准，并在 `src/backtest/metrics.py` 增加 `log_mae` 与 `spearman`；
   - 在 `TrustedValidationRegistry` 注册真实快照校验记录，运行独立样本外评估与 Walk-Forward 回测。
4. **涉及代码模块**：`src/ingestion/tech_dataset.py`、`src/diffusion/lgbm_forecaster.py`、`src/diffusion/baseline.py`、`src/backtest/engine.py`、`src/backtest/metrics.py`。
5. **开源项目借鉴点**：`allenai/prescience`（固定期轨迹、`log_mae`/`spearman`、`baseline_poisson`/`ridge`）；`microsoft/qlib`（`DataHandlerLP`, `RollingGen(label_leak_n)`）。
6. **输出成果**：首份基于真实 OpenAlex 历史数据的跨周期样本外评估报告与 Walk-Forward 回测记录。
7. **验收测试**：
   - `DataHandlerLP` 隔离测试：验证验证集标准化均值/方差严格来自训练集；
   - 基准对照测试：输出 LightGBM vs Poisson vs Ridge vs 动量基准的 `log_mae`、`mae`、`spearman`；若未击败基准则保持 `BENCHMARK` / `EXPERIMENTAL`，禁止强行晋升。
8. **依赖与风险**：10–15 个技术主题截面样本总数可能仍偏小（约 60–100 条），需警惕过拟合，若真实数据下模型表现不如 Ridge/Poisson 须如实接受结论并简化模型。
9. **完成条件**：所有评估结论有真实快照哈希与 `pytest` 回归保障，CI 全绿。

## 第四阶段：产业商业化及资产映射（P1）

1. **目标**：打通 Task B（代表企业真实财务与违约队列）与 Task C（可交易资产全收益标签），替换 `enterprise.py` 硬编码元组与 `asset_mapping.py` 静态估值，并修复 `survival_cox.py` 上游假财务注入。
2. **输入**：公开无密钥财经接口（如 AKShare 历史财报、ST/退市公告、复权日线行情与分红除权数据）。
3. **具体功能**：
   - 重构 `src/ingestion/enterprise.py`：拉取真实财报公告并严格记录年报首次公告日 `published_at`，保留原始响应快照与 SHA-256；
   - 清除 `opportunity_pool.py:160` 硬编码 `topic_financials` 与 `survival_cox.py:434,437` 静默默认值；
   - 将 `src/value_chain/financial_audit.py` 接入 `OpportunityPoolManager` 与 `ResearchDossierGenerator` 第 7 章；
   - 重构 `src/payoff_engine/asset_mapping.py` 接入真实标的代码与复权行情，支持 Task C 独立验证。
4. **涉及代码模块**：`src/ingestion/enterprise.py`、`src/value_chain/financial_audit.py`、`src/risk_survival/survival_cox.py`、`src/payoff_engine/asset_mapping.py`、`src/decision_engine/opportunity_pool.py`、`src/reporting/dossier.py`。
5. **开源项目借鉴点**：`OpenBB` 统一适配器接口设计思想（不强引入重型框架）。
6. **输出成果**：真实财报与复权行情入库管道 + 企业级健康度真实审计报告 + 消除全部手写业务假数据。
7. **验收测试**：
   - PIT 公告日测试：验证 `2020-12-31` 查询不可见 `2021-04-28` 才发布的 2020 年年报；
   - 缺失协变量测试：缺 `cash_burn_months` 或 `competitor_count` 时不再静默填 `24.0`/`1.0`。
8. **依赖与风险**：第三方公开财经接口可能存在限流或字段变更，需保留本地快照缓存与字段契约校验。
9. **完成条件**：`enterprise.py` 不再依赖 `MANUAL_REFERENCE` 支撑正式验证，CI 全绿。

## 第五阶段：自动化研究与模型持续迭代（P2）

1. **目标**：借鉴 `RD-Agent` 模式建立结构化“假设—实验—验证—留存/拒绝”台账，将人工/Agent 调优过程转化为可审计、可复现的实验记录。
2. **输入**：第一至四阶段积累的真实版本化数据集（`data_version`）与基准评估指标。
3. **具体功能**：
   - 在 DuckDB 新增 `research_experiments` 台账表（记录 `hypothesis_id`、`data_version`、`git_commit_sha`、`feature_version`、`model_params`、`random_seed`、`oos_metrics`、`status`、`failure_reason`）；
   - 实现轻量级实验编排器：允许研究 Agent 提出特征假设，由沙箱跑通样本外评估并与当前 SOTA（`Trace.get_sota_hypothesis_and_experiment`）对比，仅当样本外指标严格优于 SOTA 且通过 `ModelValidationService` 时才允许记录为候选晋升；
   - 在 `src/api/app.py` 完成读写分离与 FastAPI `TestClient` 全端点测试覆盖。
4. **涉及代码模块**：`src/core/database.py`、`src/decision_engine/`（实验追踪模块）、`src/api/app.py`、`tests/test_api.py`。
5. **开源项目借鉴点**：`microsoft/RD-Agent`（`Hypothesis`、`HypothesisFeedback`、`Trace`）。
6. **输出成果**：结构化可复现实验台账 + 受控半自动研究工作流 + 健壮的只读/异步分离 API。
7. **验收测试**：
   - 复现性测试：同一 `data_version` + `random_seed` + `git_commit_sha` 两次运行指标完全一致；
   - 失败拦截测试：未击败基准或缺失 `raw_hash` 的实验自动标记为 `REJECTED`，不得更新 SOTA；
   - `TestClient` 覆盖 `app.py` 全部 7 个接口。
8. **依赖与风险**：依赖前四阶段真实数据底座；严禁赋予实验 Agent 自动修改 `model_validator.py` 或 `AGENTS.md` 门禁的权限。
9. **完成条件**：全系统无硬编码业务假数据、三类任务预测物理隔离、CI 门禁全绿并通过独立审查。
